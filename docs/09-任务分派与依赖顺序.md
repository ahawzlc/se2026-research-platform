## 二、依赖关系与执行顺序

同一批次内的任务互不依赖、可并行：

1. **A-1 注册/登录/me**（唯一零依赖的业务卡，全组咽喉）＋ **D 前期工作**（验收脚本、答辩素材，与任何人无依赖）
2. **A-2 课题组**、**C-4 文件上传** ← 只等 A-1；C-4 虽排在第 4 周，C 组有空应提前做（C-1、C-3 都压在它上面）
3. **B-1 项目与里程碑**、**C-2 会议**、**C-3 成果**、**A-补1/补2（个人资料、改密）** ← 只等 A-2（拿到真实团队上下文）
4. **B-2 任务看板**、**B-补1 项目概览（可同段开工）** ← 等 B-1
5. **B-3 任务评论** ← 等 B-2；**C-1 文献管理** ← 等 C-4（不依赖 B 线，与上一批并行）；**C-5 消息** ← 等 A-2，弹性可后置
6. **D-1 参与度统计接口** ← 等 B-2/B-3/C-1/C-2/C-3 实际产生埋点数据（否则接口只能返回空）
7. **D-2 画像可视化** ← 等 D-1；同期做权重校准
8. **第 8 周收尾**：全链路联调、性能兜底、答辩材料、打 `v1.0` —— 等所有模块

**关键路径**：`A-1 → A-2 → B-1 → B-2 → B-3 →（埋点数据齐）→ D-1 → D-2 → 联调答辩`。这条链上任何一环拖延，最终验收直接顺延，**A-1 应立即开工**。C 线（`C-4 → C-1 / C-2 / C-3`）与 B 线并行，第 5 周中期验收前走完即可。
