## 0. 全局上下文（所有线共用，交给 AI 时必附本节）

### 0.1 项目与技术栈

- 项目：校园科研项目协作与成果管理平台。前后端分离 monorepo：`backend/`（NestJS 11 + TypeScript + Prisma 6 + MySQL 8）+ `frontend/`（Vue 3.5 + Vite + Element Plus + Pinia）+ `deploy/`（Docker Compose 三容器：mysql / backend:8080 / web/nginx:80，仅 80 端口对外）。
- 全局 API 前缀 `/api/v1`，统一返回体 `{code, message, data}`，认证为 Passport-JWT Bearer（7 天有效），接口文档 `/api/v1/docs`（Swagger）。
- CI：`.github/workflows/deploy.yml`，develop 分支 push 后 scp 到组服务器重建容器。**当前 CI 不跑任何测试（T-0 卡将补上）。**

### 0.3 全局红线（摘自 docs/08，全部适用，全文以 docs/08 为准）

1. **表结构三步走**：改 `docs/02-数据字典.md` → `deploy/mysql/init/01-schema.sql` → `backend/prisma/schema.prisma`，三处同步，一个 PR 内完成。**禁止 `prisma migrate` / `prisma db push`**。
2. **外键与 Prisma 严格对齐**（2026-11-03 起：约束名 `<表>_<列>_fkey`、RESTRICT / 可空 SET NULL / UPDATE CASCADE；多态引用列 `ref_type/ref_id` 除外），**全库逻辑删除**（`deleted` 列 0/1），列表与详情查询必须过滤已删除数据。
3. **所有查询带归属条件**（团队/作者标识），权限判断在 service 层做，不信 JWT roles。
4. **流程**：main 保护分支 + develop + feature 分支，中文 Conventional Commits，PR 至少 1 人审查后才可合入。
5. **AI 执行边界**（docs/08 第四节）：AI 可以写核心代码，但产出**停在 feature 分支 + PR**，等组员人工审查后合入；开发留痕按 docs/10、docs/11 的模式补到本线留痕文档。

### 0.4 测试完成定义（DoD，每张功能卡统一追加）

1. 本卡 service 单测覆盖主分支 + 失败分支（无权限、参数非法、状态机非法流转）；
2. 真库集成测试至少 1 条 happy path + 1 条权限负例（跨组/越权必须 403 或 404）；
3. 卡片完成时在 `docs/14-测试计划与报告.md`（T-3 建）对应迭代小节登记用例与结果。

### 2.4 防卡机制（一人一线制的配套纪律）

1. **接缝先行**：唯二跨线依赖在 W1 冻结成接口，之后任何人都不需要等别人；
2. **线内自排序**：每条线内部卡片顺序自己定，卡 stuck 时先跳线内下一张卡；
3. **卡片可转手**：每张卡自带用户故事/验收清单/AI 开工指令，接手成本 ≤ 半天——某线卡壳 >2 天，牵头协调换人、拆卡或降档，不停整线；
4. **交叉审查配对**：线② ↔ 线③、线④ ↔ 线① 互审 PR，防知识孤岛，也天然培养"能接手别人线"的第二人选；
5. **周日 15 分钟同步**（群内文字）：各线报进度与风险，卡壳升级当场定对策；
6. **单点风险预案**：线主遇考试周提前两天报，线① 的弹性工时优先支援关键路径（线②）。

### 卡 T-0：测试进 CI / PR 门禁（必须，W1 落地）

**一句话**：让 develop 部署前和每个 PR 上自动跑测试，测试从"存在"变成"门禁"。

**要做什么**：

1. 本地先确认 `backend npm run test`、`frontend npm run typecheck && npm run lint` 全绿（不绿先修）；
2. 改 `.github/workflows/deploy.yml`：新增 `test` job（backend：`npm ci` + `lint` + `test`；frontend：`npm ci` + `typecheck` + `lint`），触发条件加 `pull_request`；deploy job 加 `needs: test`；
3. 现有测试全是 mock 数据库，runner 不需要 MySQL 即可跑；为 T-1 系列预留的 MySQL services 配置写在 PR 描述里给其他线参考。

**验收**：故意把一个断言改红提 PR，CI 拦下；恢复后 CI 绿灯。

**交给 AI 的开工指令**：

### 卡 G-0：表结构先行 PR（必须，W1 合入）

**一句话**：6 张新表 + 1 个枚举扩展一次性设计合入，避免四条线并行改同一个 `01-schema.sql` 冲突。

**新表清单**（DDL 初稿由本卡产出，第 8 节决策点过会后定稿）：

| 表 | 用途 | 关键约束 |
| --- | --- | --- |

**验收**：CI 绿；线②③④评审通过合入；`docker compose exec mysql mysql < 01-schema.sql` 在本地可重放。

### 卡 G-1：通知中心（必须，横切地基）

**一句话**：顶栏铃铛 + 站内通知列表，是线②③④的公共依赖。

**用户能看到什么**：

- 登录后顶栏多一个铃铛图标；有未读通知时显示数字角标（未读数随 30 秒轮询刷新，与消息页未读同节奏）；
- 点铃铛展开最近通知：每条一行，格式如「张三 申请加入你的帖子《互联网+项目》」「李四 通过了你的好友申请」「会议《需求评审》将于 14:00 开始」；未读条目加粗；
- 点某条通知：标记已读并跳到来源（帖子详情 / 好友页 / 会议详情 / 私信会话）；
- 通知列表页可「全部已读」；
- 通知只增不改、暂不清理历史。

**技术要点**：

- 表：G-0 的 `notification`；type 枚举本期含 `team_apply / team_apply_approved / team_apply_rejected / friend_request / friend_accepted / meeting_upcoming`（最后一个线④ F-2 用，先占位）；
- 接口方向（最终以 docs/01 更新为准）：`GET /api/v1/notifications?unreadOnly=&page=`、`PATCH /notifications/:id/read`、`PATCH /notifications/read-all`；
- **W1 就要冻结的公共接口**（其他线靠它开工）：`NotificationService.push({ toUserId, type, title, refType, refId })`，幂等由调用方保证；先出接口签名 + 带 mock 的空实现 + 单测给线②③④并行，W2 完成真实实现；
- 前端：`BasicLayout` 顶栏铃铛 + `/notifications` 页面 + `frontend/src/api/notifications.ts`。

**与其他线的接缝**：E-2 调 push 三处、E-3 调 push 两处、F-2 cron 调 push 一处；铃铛角标轮询接口与消息页未读共用 30 秒节奏，注意两个角标不要互相覆盖。

**验收清单**：

- [ ] 未读数正确（已读/全部已读后角标归零）
- [ ] 点击通知跳转来源正确且变已读
- [ ] push 接口有单测（含 refType/refId 缺省分支），W1 内签名冻结并通知线②③④
- [ ] docs/01 已更新并同步 E-2/E-3/F-2 认领人

### 卡 F-3：我的待办·跨项目聚合视图（考虑，飞书对标首选项，W4–5）

**验收**：多个项目有任务时聚合与排序正确；逾期红标口径与看板一致。

**实现留痕（2026-11-26，PR #49）**：工作台用既有 `assigneeId` 任务查询按页聚合本人未完成任务；筛选、排序和逾期判断复用公共函数；看板也读完项目任务分页。卡片、看板、横幅与甘特图按同一本地日期判断逾期。本周到期为今天至本周日（含边界），昨天及更早由逾期筛选承接。未新增后端接口或表。初版 `5ac5e87` 的 Ubuntu 前端 30 条测试、typecheck、lint、build 已通过；本轮复审修复已在 Ubuntu 虚拟机通过两时区各45条测试、8个变体、静态检查及浏览器复测。详见 `docs/19-线④F-3开发留痕.md`。
