# 线④ F-3：我的待办·跨项目聚合视图

开发基线：develop `1d94566`（含 PR #47 / Issue #48）。初版提交 `5ac5e87`，PR #49。本轮按 PR #49 复审修复；不新增后端接口、表或迁移，不修改 `mine=true` 的既有缺陷。

## 实现与边界

- “我的待办”用 `GET /api/v1/tasks?assigneeId=<当前用户id>&page=&size=100` 跨项目分页，服务端仍按当前用户的课题组权限过滤。权限不会改为由前端负责。
- 不再先列前 100 个项目、再拉每个项目的所有任务。`loadOverview()` 恢复无参数和原有统计查询范围；独立的 `loadMyTasks(userId)` 负责待办。
- `selectMyTasks` 是负责人/未完成过滤纯函数；`filterMyTasks` 是日期筛选和排序纯函数；`fetchAllTasks` 封装异步分页，被待办和看板复用。
- 全部按截止日期升序，同日期按标题排序；无日期置底。逾期为截止日期早于本地今天且未完成。本周到期为今天至本周日（含边界）；无日期不进入两个日期筛选。
- `today()`、临期三天计算统一使用浏览器本地日历日期。卡片、顶部横幅、项目概览、看板、甘特图共享日期或逾期函数。
- store 无用户信息时先读 `/auth/me`，随后把返回 id 传给真实待办加载器。待办、汇总、会议独立加载，一处失败不牵连另外两处。
- 卡片显示加载态、失败重试、空态；radio 使用 `value`。点击跳到对应项目看板，看板读取全部分页，避免第 101 条之后的任务找不到。
- 首次进入时父布局可能仍与工作台各请求一次 `/auth/me`；本轮没有改动用户 store 的全局缓存机制。
