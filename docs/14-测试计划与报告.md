## 四、缺陷流程（全组生效）

1. **登记**：发现缺陷 → 开 GitHub Issue，打 `bug` 标签 + 严重度标签（见下表），写清复现步骤与期望行为；
2. **修复**：从 develop 拉 `fix/` 分支 → 修复 → **PR 必须附带一个防复发测试用例**（单测或集成测试，能先红后绿）；
3. **关闭**：PR 审查合入后关联关闭 Issue；防复发用例登记进第二节用例表。

| 严重度 | 定义 | 时限 |
| --- | --- | --- |
| P0 | 主链路不可用（登录/部署失败/数据丢失风险） | 当天修 |
| P1 | 功能错误但有绕行（权限漏判、状态机错流转） | 2 天内 |
| P2 | 体验问题（展示错、文案错、边界未处理） | 迭代内 |
| P3 | 优化建议 | 排期 |

## 五、覆盖率口径与门槛

- 命令：`backend` 目录内 `npm run test:cov`（**勿用 `npm --prefix` 从根目录跑**，有 cwd 怪癖会扫到全仓）；
