# D 组开发与验收记录

本轮目标：交付 D-1 可独立验证的参与度统计、明细和周趋势数据源，以及 D-前期验收准备。功能分支 feature/d1-participation-stats，PR 面向 develop；不合并、不部署。

## 已实现与边界

- GET /api/v1/stats/contribution：六维归一化、综合参与指数、样本提示、当前有效行为的周分布。
- GET /api/v1/stats/contribution/details：计入/排除原因、成员/维度筛选、标准分页。
- 同组鉴权、软删过滤、字符串 id、北京时间、只读一致性事务；未知类型与非评论消息不计入。
- 当前任务状态快照撤销 task_done；权重按当前配置重算。详细口径见 docs/03 第九节，随本 PR 一并评审。
- D-2 页面、B/C 真实埋点接入与并发幂等、真实业务端到端验收、权重校准和线上双验收未完成。不能把测试样本称为真实调研或真实使用数据。
- 不变更表结构、依赖版本、事件类型、协作规范或部署工作流。

## 可重复验证

后端：npm ci；npx prisma generate；npm run build；npm test -- --runInBand；npm run test:e2e -- --runInBand；npx eslint '{src,apps,libs,test}/**/*.ts'。
前端：npm ci；npm run build；npm run lint。

HTTP e2e 使用真实 AppModule/JWT/DTO/统计服务、替身 Prisma，验证权限与错误响应、查询隔离条件、BigInt、时区、分页和容量上限；不等价于真实 MySQL 联调。
修复旧底座 e2e 的 /auth/me id 契约与数据库依赖，另修复改密单测 mock 参数的类型声明，使完整 lint 可执行。

对已运行的本地或测试环境，先注册/登录并创建或加入课题组，再在终端设置 BASE_URL、TOKEN、TEAM_ID，执行：

```bash
node scripts/acceptance/d1-smoke.mjs
```

脚本仅发 GET，不创建用户或日志；TOKEN 不写文件、不输出。不要用 dev-token 伪造不存在的用户。空数据时也应通过；有写入并发时，各请求是独立快照。

## D-前1 后续各卡验收清单

- A-1：注册/重复 409/错密 401/弱密码 400/me 字符串 id；注册登录零埋点。
- A-2：双账号建组入组/重复 409/跨组 403/非 owner 改角色 403；零埋点。
- A-补1/补2：空资料 400/本人修改/弱新密码 400/改密后新旧密码登录；零埋点。
- B-1：跨组隔离/分页/完成里程碑同事务写 milestone_done。
- B-2：创建写 task_create/完成写 task_done/重复请求与并发不重复/回退画像撤销/重做恢复单次计入/刷新保序。
- B-3：使用现有 conversation/message 表，无独立 comment 表；每条评论日志 refId=message.id，11 条评论业务仍成功但只计 10 条；失败事务无孤儿日志。
- C-4：未登录 401/白名单/超限/UUID 防穿越/回读内容；上传底座零埋点。
- C-1：文献登记与已读各写对应事件，分别单日最多 5 条；附件底座不重复计入；同文献重复标记不重复。
- C-2：创建与每位真实参会人分别写 meeting_create/meeting_attend，同人同会只计一次。
- C-3：登记写 achievement_submit，contribution_note 不影响统计，不能按关联成员自述自动分摊。
- C-5：群聊、私信均零埋点、未读隔离；不得把 message 条数作为参与度。

这些清单是待 B/C 交付后执行的契约，尚未存在的业务接口没有通过验收。业务埋点应使用 recordInTransaction；不可同时用装饰器重复写入。业务写入者须从已校验对象推导 teamId，不能信任请求体里的团队。
