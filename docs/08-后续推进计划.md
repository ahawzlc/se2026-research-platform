## 三、红线（违反即缺陷）

1. **口径**：对外一律说「参与度 / 活跃度」。**不得出现「贡献度」作为对人的评价性表述**（接口路径 `stats/contribution` 是既存命名，保留，但界面文案与文档措辞必须用「参与度」）。私信不计入统计。
2. **返回体**：`{ code, message, data }`；`code` 只能是 `0 / 400 / 401 / 403 / 404 / 409 / 500`。控制器直接 `return` 数据，出错 `throw BizException.xxx()`，不要自己拼响应体。
3. **id 一律字符串**：Prisma BIGINT 主键经 `src/common/bigint.ts` 序列化为字符串。前端 `id` 类型是 `string`，禁止当数字运算。
4. **时间**：库里存 UTC，对外用 `formatDateTime()` / `formatDate()` 转北京时间。不要在前端做时区换算。
5. **逻辑删除**：所有查询必须显式 `where: { deleted: 0 }`，Prisma 不会自动过滤。
6. **禁止** `prisma migrate dev` / `db push` / `db pull`：表结构唯一来源是 `deploy/mysql/init/01-schema.sql`。要改表按 `docs/02 → 01-schema.sql → schema.prisma` 三步走。
7. **表间不加外键**：`schema.prisma` 里是逻辑关系，一致性由应用层保证。
8. **埋点类型不可自造**：`ActivityType` 固定 9 个（见 `activity.constants.ts`）。没有「用户注册」这类类型，注册不要加埋点；新增类型须先改 `docs/03`。
9. **越权查询**：所有涉及课题组/项目数据的查询必须带团队标识条件（`team_id` 或经 `project_member` 校验）。

## 四、任务卡

### 卡 A-1｜注册、登录、当前用户

- **目标**：把 `/auth/register`、`/auth/login` 从「不存在」补到可用，`/auth/me` 从「只回令牌载荷」改为查库返回真实用户。
- **接口**：`POST /api/v1/auth/register`、`POST /api/v1/auth/login`、`GET /api/v1/auth/me`（已在 `docs/01` 冻结）。
- **涉及表**：`user`。
- **要点**：
  - 密码用 `bcryptjs`（依赖已装）hash 后入库，登录 `compare`；**不存明文、不存可逆加密**。
  - `username` 已有唯一索引，重复注册返回 `409`，不要返回 `500`。
  - 登录成功复用 `AuthService.sign()` 签发令牌，载荷 `{ sub, username, roles }`。
  - `/auth/me` 返回 `id / username / nickname / email / createdAt`，**`id` 必须是字符串**。
  - 不要在注册流程里加埋点（红线 8）。
- **验收**：
  ```bash
  curl -X POST http://82.156.156.94/api/v1/auth/register \
    -H 'Content-Type: application/json' \
    -d '{"username":"zhangsan","password":"Test1234","nickname":"张三","email":"z@example.com"}'
  # 期望 code:0，data.token 非空；重复调用期望 code:409
  ```
  再用 token 请求 `/auth/me`，确认返回真实昵称、`id` 为字符串。
- **依赖**：无，可立即开始。做完后前端登录页即可真正跑通。

### 卡 A-2｜课题组与角色

- **目标**：创建课题组（返回邀请码）、凭邀请码入组、成员列表、改角色。
- **接口**：`POST /teams`、`POST /teams/join`、`GET /teams/{id}/members`、`PUT /teams/{id}/members/{userId}/role`。
- **涉及表**：`team`、`team_member`。
- **要点**：邀请码需唯一且不可猜测；入组重复返回 `409`；改角色仅 `owner` 可操作，越权返回 `403`；成员列表禁止返回 `password_hash`。
- **依赖**：卡 A-1（需要登录态与真实 userId）。

### 卡 B-1｜项目与里程碑

- **目标**：项目增删改查（分页）+ 里程碑维护。
- **接口**：`/api/v1/projects`、`/api/v1/projects/{id}`、`/api/v1/milestones`、`/api/v1/milestones/{id}`。
- **涉及表**：`project`、`project_member`、`milestone`。
- **要点**：列表按 `page`/`size`（从 1 开始，上限 100）；只能看到自己所在课题组的项目；里程碑完成时写埋点 `milestone_done`。
- **依赖**：卡 A-1、A-2。

### 卡 B-2｜任务看板

- **目标**：任务增删改查、状态流转（拖拽换列）、看板排序持久化。
- **接口**：`POST/GET /api/v1/tasks`、`PUT /api/v1/tasks/{id}/status`、`PUT /api/v1/tasks/{id}/order`。
- **涉及表**：`task`。
- **要点**：创建写 `task_create`，状态流转到「已完成」写 `task_done`（**只写一次**，反复拖拽不能重复计分）；`order` 用整数间隔分配，避免每次全表重排。
- **依赖**：卡 B-1。

### 卡 B-3｜任务评论

- **目标**：任务下评论的读取与发表。
- **接口**：`GET/POST /api/v1/tasks/{id}/comments`。
- **涉及表**：`comment`（若无独立表则用 `task_comment`，以 `docs/02` 为准）。
- **要点**：写埋点 `comment_create`，受 `ACTIVITY_DAILY_LIMIT` 单日 10 条上限约束（防刷）。
- **依赖**：卡 B-2。

### 卡 C-1｜文献管理

- **目标**：文献增删改查 + 标签 + 阅读状态。
- **接口**：`/api/v1/literatures`、`/api/v1/literatures/{id}`。
- **涉及表**：`literature`、`literature_tag`。
- **要点**：上传写 `literature_upload`，标记已读写 `literature_read`（单日上限 5）；附件走卡 C-4 的上传接口。
- **依赖**：卡 A-1、A-2、C-4。

### 卡 C-2｜会议记录

- **目标**：会议增删改查 + 参会人。
- **接口**：`/api/v1/meetings`、`/api/v1/meetings/{id}`。
- **涉及表**：`meeting`、`meeting_attendee`。
- **要点**：创建写 `meeting_create`，签到写 `meeting_attend`（同一会议同一人只记一次）。
- **依赖**：卡 A-1、A-2。

### 卡 C-3｜成果登记

- **目标**：成果增删 + 成员关联。
- **接口**：`POST/GET/DELETE /api/v1/achievements`、`/api/v1/achievements/{id}`。
- **涉及表**：`achievement`、`achievement_member`。
- **要点**：提交写 `achievement_submit`；`achievement_member.contribution_note` 仅供展示，**不参与任何计算**（红线 1）。
- **依赖**：卡 A-1、A-2。

### 卡 C-4｜文件上传

- **目标**：统一上传接口，返回文件标识；文件落 `/data/uploads`（已挂卷）。
- **接口**：`POST /api/v1/files/upload`。
- **涉及表**：`file`。
- **要点**：限制大小（与 Nginx `client_max_body_size 50m` 一致）、限制扩展名白名单、文件名用 UUID 重写防路径穿越；返回的 URL 走 `/api/v1/files/<storedPath>`。
- **依赖**：卡 A-1。**建议优先做**，C-1 与 C-3 都依赖它。

### 卡 C-5｜协作消息（弹性功能）

- **目标**：会话消息拉取/发送、未读汇总（前端 3–5 秒轮询）、标记已读。
- **接口**：`/api/v1/conversations/{id}/messages`、`/api/v1/conversations/unread`、`/api/v1/conversations/{id}/read`。
- **涉及表**：`conversation`、`conversation_member`、`message`。
- **要点**：**消息不产生任何埋点**（红线 1，私信/群聊不计分）。
- **依赖**：卡 A-1、A-2。属于弹性功能，中期验收后可做。

### 卡 D-1｜参与度统计接口

- **目标**：按 `activity_log` 聚合出成员参与度，支持下钻到行为明细。
- **接口**：`GET /api/v1/stats/contribution?teamId=`（路径沿用 `docs/01`）。
- **涉及表**：`activity_log`（只读）、`team_member`、`user`。
- **要点**：权重只能取自 `ACTIVITY_DEFAULT_WEIGHT`，禁止在查询里硬编码数字；归一化方式见 `docs/03` 第四节；样本量过小时接口要返回样本量字段，供界面提示「数据不足」。
- **依赖**：B/C 各模块已产生埋点数据（否则只能返回空）。

### 卡 D-2｜参与度画像可视化

- **目标**：雷达图/柱状图展示成员各维度参与度，点开可看行为明细。
- **位置**：`frontend/src/views/`，路由挂在布局内。
- **要点**：ECharts 按需引入；界面必须标注「仅为过程可视化，不构成科研贡献评价」；无数据时给空状态而非 0 分。
- **依赖**：卡 D-1。

## 六、给 AI 的执行须知

**可以做**
- 环境与部署排错、脚本、CI 配置、`docs/` 下的文档整理；
- 语法问题解答、报错定位、代码审查（指出问题，不代写实现）；
- 生成测试用例与验收脚本；
- 解释既有代码（例如「`TransformInterceptor` 怎么包装返回值」）。

**不要做**
- **不要直接产出业务模块的实现代码**。课程明确要求作业代码由组员自己写，AI 代写属于违规；
- 不要改 `deploy/mysql/init/01-schema.sql` 与 `docs/02` 的表结构（要改必须先与全组确认）；
- 不要升级后端依赖版本（`backend/README.md` 第十节列了钉选原因，`npm update` 会炸）；
- 不要提交 `.env` / `.env.prod` / 私钥；
- 不要顺手「优化」无关文件——一次改动只针对一张任务卡。

**每次改动后的自检**
1. `cd backend && npm run build`、`cd frontend && npm run build` 均无错误；
2. `npm run lint` 通过；
3. 用 `git status` 确认只改动了预期文件；
4. 提交信息符合 `type(scope): 中文描述`，不带句号；
5. 涉及接口的改动，同步更新 `docs/01`；涉及表结构的，走三步走流程。

## 七、风险与预案

| 风险 | 影响 | 预案 |
| --- | --- | --- |
| 业务接口未实现，线上登录页点不动 | 演示受阻 | 属预期。A-1 完成后自然恢复；过渡期用 `dev-token` 手工签令牌测受保护接口 |
| 埋点漏写或重复写 | 参与度数据失真，答辩被追问 | 每个写操作显式检查埋点；`task_done` 等状态型埋点必须做幂等（同对象只记一次） |
| 多人同时改同一张表 | 冲突返工 | 表结构变更集中在 `docs/02` 评审，代码按模块分目录，减少同文件冲突 |
| 线上库被误操作（`down -v`、误删表） | 数据丢失 | 每日 03:30 自动备份已开；演示前把最新备份拉到本地一份 |
| 2C4G 机器资源吃紧 | 构建 OOM、接口变慢 | 已限制 MySQL 内存与连接数；`deploy.sh --no-cache` 不要在演示前 10 分钟跑 |
| 中期验收功能不全 | 分数受损 | 第五周的验收只要求「核心协作闭环」，弹性功能（消息）可后置 |
