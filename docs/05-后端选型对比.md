# 后端选型对比：Spring Boot 3 ↔ NestJS

实现方案里写明「后端语言提供两套等价方案，按熟悉程度二选一，**一旦确定不得中途更换**」。
本文件把两条路的**优缺点、依赖清单、环境要求、踩坑点**摊开，供 A 组拍板并在答辩时说明理由。

> 拍板前请看第三节（决策清单）——这个决定的关键不是技术优劣，而是**组内谁能在第 1 周独立写出一个能跑通的分层 CRUD + JWT 登录**。

---

## 一、先看本项目真正吃后端的地方

不是"哪个语言更好"，而是这四个需求谁做得快（按工作量从大到小）：

| 需求 | 工作量 | 说明 |
| --- | --- | --- |
| **18 张表的 CRUD** | 最大 | 账号 3 + file 1 + 业务 10 + 沟通 3 + activity_log 1，占后端工时的绝对大头 |
| **统一埋点** | 关键路径 | 必须与业务写入同事务，第 1 周就要能用，否则贡献度无数据可算 |
| **鉴权与统一返回体** | 中等 | JWT + 角色（负责人/管理员/成员）+ `{code,message,data}` + 全局异常 |
| **贡献度聚合计算** | 中等偏难 | 同对象去重、单日上限截断、按维度聚合、团队内归一化、按周趋势、明细下钻——本质是复杂 SQL |

外加：文件上传（文献/成果附件）、接口文档、Docker 部署。**这四条谁做得顺手，就选谁。**

---

## 二、逐项对比

| # | 维度 | 方案一 Spring Boot 3 + Java | 方案二 Node + NestJS | 对本项目的实际影响 |
| --- | --- | --- | --- | --- |
| 1 | **26 表 CRUD 效率** | ⭐ MyBatis-Plus Generator 能一次性生成 18 张表的 entity/mapper/service/controller | Prisma 生成 client，但 service/controller 仍需手写（`nest g resource` 只给空骨架） | **方案一明显省工时**，这是 18 张表项目最大的效率差 |
| 2 | **埋点实现** | ⭐ AOP + 自定义注解 `@ActivityLog`，控制层打一个注解即可，且天然与 `@Transactional` 同事务 | Interceptor + `@SetMetadata` 装饰器同样可行，但要把事务上下文传给拦截器，需 `AsyncLocalStorage` 或显式传参 | 两者都能做；Java 的写法**更贴埋点"无侵入"的初衷** |
| 3 | **贡献度复杂 SQL** | ⭐ MyBatis XML 直接写窗口函数 / CTE / `GROUP BY HAVING`，可读性好 | Prisma 的复杂聚合要 `$queryRaw` 逃逸；TypeORM QueryBuilder 可写但啰嗦 | 贡献度是**亮点模块**，SQL 越顺越好 |
| 4 | **前后端类型共享** | 靠 Knife4j 导出给前端，多数手写 | ⭐ 前后端同语言 TS，接口类型/校验规则可共用 | 方案二在联调期省一些字段对不上的扯皮 |
| 5 | **中文资料与脚手架** | ⭐⭐ 极多（后台管理类教程、若依等现成脚手架） | 中文资料偏少，官方文档质量高但需读英文 | 8 周内遇到卡点，方案一更容易搜到答案 |
| 6 | **版本兼容坑** | 多：`javax`→`jakarta` 导致**网上大量 SB2 教程直接不能用**；MyBatis-Plus 要选 `spring-boot3` 版本；Lombok 需 1.18.30+ 才支持 JDK 21 | 中：装饰器需要 TS 配置、ESM/CJS 混用、TS 版本与 Nest 版本耦合 | 两边都有坑，**方案一的坑更"有名有解"** |
| 7 | **启动速度 / 内存** | JVM 启动 3–8 s，堆 300–500 MB | ⭐ 启动 1–2 s，内存约 150 MB | 4 人各自本机跑 + Docker 跑 MySQL 时，JVM 更吃内存，但一般够用 |
| 8 | **热重载** | DevTools 可用，够用 | ⭐ 更快（`--watch` 秒级） | 影响开发手感，不决定成败 |
| 9 | **报错可诊断性** | 堆栈长但定位明确；编译期就能挡下一批错 | 运行时类型错误更隐蔽（`undefined` 传播），靠 TS + `class-validator` 缓解 | 新手调试成本方案一更低 |
| 10 | **答辩观感** | ⭐ Spring Boot + MySQL + Redis + JWT 是评委最熟的"企业级"叙事 | 全栈 TS 可讲"同构与工程化"，但部分评委不熟 | 方案一叙事更稳 |
| 11 | **测试与 CI** | JUnit 5 + MockMvc 成熟 | Jest + supertest 也不错 | 平手，方案一略成熟 |
| 12 | **部署体积** | JRE 镜像约 200 MB 起 | ⭐ Node 镜像可压到 120 MB 左右 | 平手，都不影响验收 |

**小结**

- 方案一赢在：**CRUD 生成、AOP 埋点、复杂 SQL、资料量、答辩叙事**
- 方案二赢在：**全栈同语言、启动轻快、类型共享**

## 三、决策清单（拍板用）

按顺序回答，第一条"是"就直接定：

| 顺序 | 问题 | 若为"是" |
| --- | --- | --- |
| 1 | 组内**是否有人完整写过 Spring Boot 项目**（哪怕只是跟着教程做过带 JWT 的后台）？ | **选方案一**，效率优势能吃满 |
| 2 | 组内是否有人写过 Node 后端（Express / Nest / Koa）？ | 选方案二 |
| 3 | 是否希望前端同学也能顺手改后端（不想多学一门语言）？ | 选方案二 |
| 4 | 以上都"否"（全组只会前端 TS + 课程里的 Java 语法）？ | **选方案二**：语言与前端同源，学习曲线更缓；代价是埋点与复杂聚合要自己写得更费劲 |

> **不可逆提醒**：本决定**第 3 周后基本无法反悔**。一旦开工，换语言等于后端归零。
> 所以宁可花半天做上表第 1 题的自评，也不要"先干起来再说"。

## 四、方案一需要准备的东西

### 1. 环境（本机现状已核对）

| 项 | 现状 | 需补 |
| --- | --- | --- |
| JDK | **已有 21**（方案写 Java 17，SB 3 支持 17–21，可直接用 21） | 无需安装；注意 Lombok 需 ≥ 1.18.30 |
| Maven | **未安装** | `winget install Apache.Maven`，或用 IDEA 内置的打包器 |
| Docker | 已装（跑 MySQL 8 用） | 启动 Docker Desktop |
| IDE | — | IDEA Community 够用（Ultimate 才有 Spring 面板）；VSCode 需 Extension Pack for Java |

### 2. Maven 依赖清单（SB 3.x）

```
spring-boot-starter-web                 REST 接口
spring-boot-starter-validation          参数校验
spring-boot-starter-aop                 埋点必需
spring-boot-starter-security（可选）    也可只用 jjwt + 自写过滤器
mybatis-plus-spring-boot3-starter       注意必须 spring-boot3 版本
mysql-connector-j
lombok
jjwt-api / jjwt-impl / jjwt-jackson     0.12.x
knife4j-openapi3-jakarta-spring-boot-starter   或 springdoc-openapi-starter-webmvc-ui
spring-boot-starter-data-redis（可选）
mybatis-plus-generator + freemarker      一次性代码生成，本机跑完即可
```

### 3. 工程骨架（选定后可直接落盘）

- 分层：`controller` / `service` / `mapper` / `entity` / `dto` / `config` / `common` / `aop`
- `common`：`Result<T>` 统一返回体、错误码枚举、`GlobalExceptionHandler`、业务异常类
- `config`：MyBatis-Plus 分页插件 + 自动填充（`created_at`/`updated_at`）+ 逻辑删除（`deleted`）、CORS、Knife4j
- 鉴权：JWT 过滤器 + `SecurityConfig`（放行 `/api/v1/auth/**`）+ `@RequireRole` 角色注解
- 埋点：`@ActivityLog` 注解 + 切面 → 写入 `activity_log`
- `application-dev.yml` / `-prod.yml` 多环境，敏感项读环境变量

### 4. 特有踩坑

1. **`javax` → `jakarta`**：SB 3 换了命名空间，网上大量 SB 2 时代教程/Security 配置**复制即报错**，认准文档版本；
2. **MyBatis-Plus 版本**：必须用 `mybatis-plus-spring-boot3-starter`，普通 starter 在 SB 3 下启动失败；
3. **Lombok + IDEA 注解处理**：新装 IDE 要确认 Annotation Processing 已开，否则实体类找不到 getter；
4. **Knife4j 与 springdoc 冲突**：两者不要同时引入。

## 五、方案二需要准备的东西

### 1. 环境

| 项 | 现状 | 需补 |
| --- | --- | --- |
| Node | **已有 22**，可直接用 | 无需安装；建议定 `.nvmrc` 锁版本 |
| 包管理器 | npm 10 | 全组统一 npm 或 pnpm，**不要混用**（锁文件会打架） |
| Nest CLI | 未装 | `npx @nestjs/cli new` 直接用，无需全局安装 |
| Prisma | 未装 | `npx prisma init` |
| Docker | 已装 | 启动 Docker Desktop |

### 2. npm 依赖清单

```
@nestjs/core @nestjs/common @nestjs/platform-express
@nestjs/config                配置
@nestjs/swagger               接口文档
@nestjs/jwt @nestjs/passport passport passport-jwt   鉴权
prisma @prisma/client         数据访问（或 typeorm + @nestjs/typeorm）
class-validator class-transformer                    参数校验
bcrypt                        密码散列
multer                        文件上传
@nestjs/schedule（可选）       贡献度定时聚合
@nestjs/throttler（可选）      限流，反刷点辅助
jest ts-jest @nestjs/testing supertest               测试
ioredis（可选）
```

### 3. 工程骨架

- 模块：`auth` / `user` / `team` / `project` / `task` / `literature` / `meeting` / `achievement` / `conversation` / `activity` / `file`
- `common`：`TransformInterceptor`（统一返回体）、`HttpExceptionFilter`（全局异常）、`ValidationPipe`（全局 + `whitelist`）
- 鉴权：`JwtAuthGuard` + `RolesGuard` + `@CurrentUser()` / `@Roles()` 装饰器
- 埋点：`ActivityLogInterceptor` + `@ActivityLog()` 装饰器；事务上下文用 `AsyncLocalStorage` 传递，**或者**在 service 层显式调用（更笨但更可控，推荐前期这么干）
- `prisma/schema.prisma` 映射 18 张表，注意 **`@@map` / `@map` 做 snake_case ↔ camelCase 转换**，与 `deploy/mysql/init/01-schema.sql` 保持一致

### 4. 特有踩坑

1. **装饰器配置**：`tsconfig` 的 `experimentalDecorators` / `emitDecoratorMetadata` 必须开；
2. **Prisma 与既有 schema 的对接**：我们已有手写 DDL，要用 `prisma db pull`（反向生成）而不是 `migrate dev`（会试图重建表）；
3. **TS 类型不进运行时**：接口入参必须靠 `class-validator`，不能指望类型约束；
4. **复杂聚合要写原生 SQL**：贡献度的去重 + 单日上限建议直接 `$queryRaw`，别硬用 Prisma ORM 表达式；
5. **Nest 模块化概念**（Module / Provider / 依赖注入）对没写过的人是新心智负担，前 3 天会慢。

## 六、两方案共同的必做项（第 1 周冻结）

与语言无关，写在这里提醒不要因为选型讨论而漏掉：

1. `deploy/mysql/init/01-schema.sql` 的 **18 张表**（已落）；
2. 统一返回体 `{code,message,data}` + 错误码表（见 `01-接口规范.md`）；
3. 接口前缀 `/api/v1`、分页 `page`/`size`（从 1 开始）；
4. **`activity_log` + 全局统一埋点方法**——最关键，晚一周就无历史数据；
5. JWT 载荷设计（`user_id`、`exp`，是否需要 `team_id`）与过期策略；
6. 文件上传落地方式（本地磁盘 + 静态映射，或 MinIO）；
7. `.env` 配置项清单（只提交 `.env.example`）；
8. `backend/Dockerfile` + 接入 `deploy/docker-compose.yml`（`depends_on: mysql`）。

## 七、风险与对冲

| 风险 | 影响 | 对冲 |
| --- | --- | --- |
| **第 1 周未完成埋点** | 贡献度模块无数据可算，亮点模块塌掉 | 埋点与基础模块同批交付，选型后**第一件事**就是它 |
| 选型后中途想换语言 | 后端归零，进度不可挽回 | 拍板前认真做第三节第 1 题；拍板后写进 `MEMORY.md` 不再讨论 |
| 4 人并行改同一接口/表 | 冲突、返工 | `docs/` 为唯一口径；改表先改文档；走 PR 评审 |
| 8 周做完全部 CRUD + 推荐/选做项 | 必然延期 | 按实现方案的优先级砍：选做项超前才做，落后即砍 |
| 方案一：Maven 未装 + 版本坑 | 首日卡住 | 见第四节第 4 条，逐条预检 |
| 方案二：Prisma 反向生成误改表 | 数据库结构被覆盖 | 只用 `db pull`，禁用 `migrate dev`；建表脚本以仓库 SQL 为准 |

## 八、选定后 48 小时内可交付的东西

不论选哪个，以下内容我可以在确定后立刻落盘并提 PR：

1. 后端工程骨架（分层目录 + 配置文件 + `.env.example`）
2. 统一返回体 + 错误码枚举 + 全局异常处理
3. JWT 鉴权链路（注册 / 登录 / 令牌校验）

5. `backend/Dockerfile` + 接入 `deploy/docker-compose.yml`
6. 在线接口文档页打开，并能带 token 调通一个接口
7. 走 `feature/backend-init` → PR → `develop` 的标准流程
