-# 接口规范

本文件为前后端共同遵守的接口约定。前端封装（`frontend/src/api/request.ts`）已按本规范实现，后端请对齐同样的返回结构，否则前端需额外适配。

## 一、基本约定

| 项 | 约定 |
| --- | --- |
| 接口前缀 | `/api/v1` |
| 风格 | RESTful，用 HTTP 方法表达动作 |
| 请求/响应体 | `application/json`，文件上传除外（`multipart/form-data`） |
| JSON 字段命名 | 小驼峰（`createdAt`、`assigneeId`） |
| **主键与 id 字段** | 一律以**字符串**传输（后端 BIGINT 主键序列化为字符串），前端不要当数字做运算；详见 [06-环境终检报告.md](06-环境终检报告.md) |
| URL 路径命名 | 全小写，多单词用中划线（`/literature-tags`） |
| 时间格式 | `yyyy-MM-dd HH:mm:ss`（北京时间，后端用 `src/common/datetime.ts` 的 `formatDateTime()`）；仅日期字段用 `yyyy-MM-dd`（用 `formatDate()`）。**数据库内统一存 UTC** |
| 字符集 | UTF-8 |

## 二、统一返回体

所有接口（含错误）都返回同一结构：

```json
{
  "code": 0,
  "message": "ok",
  "data": {}
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `code` | int | 业务状态码，`0` 表示成功，非 0 表示失败 |
| `message` | string | 提示信息，成功时为 `ok`，失败时为可直接展示给用户的文案 |
| `data` | any | 数据体，失败时为 `null` |

### 业务状态码

| code | 含义 | 前端处理 |
| --- | --- | --- |
| `0` | 成功 | 取 `data` 使用 |
| `400` | 参数校验失败 | 提示 `message` |
| `401` | 未登录 / 令牌失效 | 清除本地令牌并跳转登录页 |
| `403` | 已登录但无权限 | 提示无权限，不做跳转 |
| `404` | 资源不存在 | 提示并返回列表页 |
| `409` | 状态冲突（如邀请码重复、重复入组） | 提示 `message` |
| `500` | 服务端异常 | 提示「服务异常，请稍后重试」 |

HTTP 状态码仍按语义返回（成功 200、未授权 401 等），但**前端以业务 `code` 为准**，不依赖 HTTP 状态码判断成败。

## 三、鉴权

- 需要登录的接口在请求头携带令牌：

```
Authorization: Bearer <token>
```

- 令牌由登录接口签发，前端持久化在 `localStorage`，由 Axios 请求拦截器自动注入；
- 令牌失效返回 `code: 401`，前端响应拦截器统一处理为「清令牌 + 跳登录」；
- **所有涉及课题组数据的查询，后端都必须附加团队标识条件**，防止越权访问他人数据。

## 四、分页

列表接口统一使用 `page` 与 `size` 两个查询参数：

| 参数 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `page` | int | 1 | 页码，**从 1 开始** |
| `size` | int | 10 | 每页条数，服务端限制上限 100 |

分页响应统一结构（放在 `data` 中）：

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "list": [],
    "total": 0,
    "page": 1,
    "size": 10
  }
}
```

## 五、接口清单

### 认证

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/v1/auth/register` | 注册，入参 `username`、`password`、`nickname`、`email` |
| POST | `/api/v1/auth/login` | 登录，返回 `token` 与用户信息 |
| POST | `/api/v1/auth/logout` | 登出（可选，无状态令牌下可为空实现） |
| GET | `/api/v1/auth/me` | 获取当前登录用户 |
| PUT | `/api/v1/auth/profile` | 修改个人资料，入参 `nickname`、`email`（均可选，至少传一个），返回更新后的用户信息（结构同 `/auth/me`） |
| PUT | `/api/v1/auth/password` | 修改密码，入参 `oldPassword`、`newPassword`，成功签发并返回新令牌 |

### 课题组

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/v1/teams` | 创建课题组，返回邀请码 |
| POST | `/api/v1/teams/join` | 凭邀请码入组 |
| GET | `/api/v1/teams/my` | 当前用户加入的课题组列表（含本人角色） |
| GET | `/api/v1/teams/{id}/members` | 获取课题组成员（分页） |
| PUT | `/api/v1/teams/{id}/members/{userId}/role` | 修改成员角色（仅组长） |

### 项目与里程碑

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/v1/projects` | 创建项目（创建者自动成为项目成员） |
| GET | `/api/v1/projects` | 项目列表（分页；**仅返回本课题组的项目**） |
| GET | `/api/v1/projects/{id}` | 项目详情（含成员列表与各类计数） |
| PUT | `/api/v1/projects/{id}` | 更新项目 |
| DELETE | `/api/v1/projects/{id}` | 删除项目（逻辑删除） |
| GET | `/api/v1/projects/{id}/milestones` | 项目的里程碑列表 |
| GET | `/api/v1/projects/{id}/members` | 项目成员列表 |
| POST | `/api/v1/projects/{id}/members` | 添加项目成员（入参 `userId`，须为本课题组成员） |
| DELETE | `/api/v1/projects/{id}/members/{userId}` | 移除项目成员 |
| POST | `/api/v1/milestones` | 创建里程碑（入参含 `projectId`） |
| PUT | `/api/v1/milestones/{id}` | 更新里程碑（**置为 `done` 时写 `milestone_done` 埋点**） |
| DELETE | `/api/v1/milestones/{id}` | 删除里程碑（逻辑删除） |

> **里程碑埋点口径**：状态由非 `done` 变为 `done` 时写一条 `milestone_done`，
> **同对象只计一次**；由 `done` 退回 `pending` 时撤销该条埋点。

### 任务

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/v1/tasks` | 新建任务（写 `task_create` 埋点） |
| GET | `/api/v1/tasks` | 任务查询（按项目、状态、负责人过滤；不传 `projectId` 返回本组全部） |
| GET | `/api/v1/tasks/{id}` | 任务详情 |
| PUT | `/api/v1/tasks/{id}` | 更新任务基本信息（标题、描述、负责人、优先级、截止日期） |
| DELETE | `/api/v1/tasks/{id}` | 删除任务（逻辑删除） |
| PUT | `/api/v1/tasks/{id}/status` | 任务状态流转（看板换列） |
| PUT | `/api/v1/tasks/{id}/order` | 调整看板排序 |

> **`sort_order` 策略（由 B 组确定）**：采用**整数间隔**，相邻两项差 100。
> 排序接口入参为 `beforeSortOrder` / `afterSortOrder`（目标位置前后邻居的排序值，
> 拖到列首时 `beforeSortOrder` 传 `null`），服务端取中值作为新值。
> 间隔耗尽时服务端自动整列重排兜底。
>
> **`task_done` 埋点口径**：状态流转到 `done` 时写一条 `task_done`，
> **同一 `(user_id, type, ref_type, ref_id)` 只计一次**，反复拖拽不重复计分；
> 从 `done` 退回其它状态时撤销该条埋点。

### 任务评论

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/v1/tasks/{id}/comments` | 任务下的评论列表（按时间正序） |
| POST | `/api/v1/tasks/{id}/comments` | 发表任务评论（入参 `content`，1–2000 字符） |

> **`comment_create` 埋点口径**：评论发表时写一条埋点，

### 文献

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/v1/literatures` | 创建文献（`title` 必填；`fileId` 与 `sourceUrl` 至少提供一个；可传 `tags` 数组） |
| GET | `/api/v1/literatures` | 文献列表（分页；可按 `teamId`、`projectId`、`readStatus`、`tag`、`keyword` 过滤；仅返回本课题组可见的文献） |
| GET | `/api/v1/literatures/{id}` | 文献详情 |
| PUT | `/api/v1/literatures/{id}` | 更新文献（标题、项目、附件、外链、标签；不含阅读状态） |
| DELETE | `/api/v1/literatures/{id}` | 删除文献（逻辑删除） |
| PUT | `/api/v1/literatures/{id}/read-status` | 更新阅读状态（`unread` / `reading` / `read`） |

> **埋点口径**：创建文献写 `literature_upload`（单日上限 5 条）；阅读状态变为 `read` 时写 `literature_read`（同一文献只计一次，单日上限 5 条），从 `read` 退回时撤销该条埋点。附件上传本身不写埋点（C-4 只写 `file` 表）。

## 七、D-1 统计契约

两个接口均需 JWT 与当前团队成员身份；teamId 为必填正整数字符串（BIGINT UNSIGNED 范围），details 可选 userId 同规则、dimension 取 task/achievement/milestone/meeting/literature/discussion。禁止额外参数。分页 page 默认 1、size 默认 10，上限 100。

汇总 data：teamId、modelVersion、disclaimer、sampleSize（有效事件数）、sampleThreshold、insufficientSample、hasData、dimensions（key/label/weight/max）、members（userId/nickname/hasData/index[0–1 或 null]/dimensions[key/raw/normalized]）、weekly（weekStart/count/weight）。不按指数排序，成员按 userId 排序。空样本返回空 members/weekly，不展示确定的 0 分。

明细 data 为标准 list/total/page/size；每条含 id/userId/type/refType/refId/createdAt（北京时间）、originalWeight、countedWeight、counted、reason（counted/unknown_type/invalid_ref/duplicate/inactive_task/invalid_comment/daily_limit）。最新记录在前；筛选在全组去重和限额之后执行，不能通过筛选重置额度。明细仅包含当前有效成员的日志。

模型、时间和限制见 docs/03 第九节。summary 的 weekly 即 D-1 周趋势数据源。两个 GET 接口只读，不产生埋点。
