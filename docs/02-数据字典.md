# 数据字典

本文件与 `deploy/mysql/init/01-schema.sql` 一一对应。**以本文件为口径来源**，改表先改这里。

## 一、通用约定

### 命名与类型

| 项 | 约定 |
| --- | --- |
| 表名 / 字段名 | 全小写，多单词用下划线（`team_member`、`password_hash`） |
| 主键 | 统一 `id BIGINT UNSIGNED AUTO_INCREMENT` |
| 字符集 | `utf8mb4` / `utf8mb4_unicode_ci` |
| 存储引擎 | InnoDB |
| 金额/权重 | `DECIMAL`，不用浮点 |
| 枚举字段 | 用 `VARCHAR` 存字符串字面量（可读性优先），取值在建表注释中列明 |

### 每张表都带的公共字段

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | BIGINT UNSIGNED | 主键，自增 |
| `created_at` | DATETIME | 创建时间，默认当前时间 |
| `updated_at` | DATETIME | 更新时间，更新自动刷新 |
| `deleted` | TINYINT UNSIGNED | 逻辑删除：`0` 正常，`1` 已删除 |

例外：`activity_log` 为**只增不改**的行为流水，仅保留 `created_at`，不含 `updated_at` 与 `deleted`。

> **逻辑删除的注意事项**
> 逻辑删除后记录仍占位，会影响唯一索引。例如 `user.username` 加了唯一索引后，已删除用户的用户名无法再被注册。第一版接受该限制并在昵称/用户名上给出「已被占用」提示；若后期需要释放，可把唯一索引改为 `(username, deleted)` 组合索引，或引入 `deleted_at` 时间戳参与唯一键。

## 四、沟通类

三张表构成统一会话模型：**上下文评论、项目讨论区、成员私信共用同一套结构**，仅以 `type` 区分。

| `type` | 语义 | `ref_type` / `ref_id` |
| --- | --- | --- |
| `comment` | 锚定在业务对象上的评论 | 指向 `task` / `achievement` / `meeting` 等 |
| `group` | 项目讨论区 | 指向 `project` |
| `private` | 成员私信 | 为空 |

### conversation 会话

| 字段 | 类型 | 允许空 | 说明 |
| --- | --- | --- | --- |
| `type` | VARCHAR(20) | 否 | `comment` / `group` / `private` |
| `ref_type` | VARCHAR(30) | 是 | 业务对象类型，私信为空 |
| `ref_id` | BIGINT UNSIGNED | 是 | 业务对象主键，私信为空 |
| `title` | VARCHAR(200) | 是 | 会话标题（群组用） |

索引：`idx_conversation_ref (ref_type, ref_id)`。

### conversation_member 会话成员与已读位点

| 字段 | 类型 | 允许空 | 说明 |
| --- | --- | --- | --- |
| `conversation_id` | BIGINT UNSIGNED | 否 | `conversation.id` |
| `user_id` | BIGINT UNSIGNED | 否 | `user.id` |
| `last_read_at` | DATETIME | 是 | 最后已读时间，**未读数的唯一依据** |

索引：唯一 `uk_conversation_member (conversation_id, user_id)`；`idx_cm_user (user_id)`。

> **未读数算法**：`未读数 = COUNT(message WHERE conversation_id = ? AND created_at > last_read_at)`。
> 该设计只需一条查询语句，不为每条消息维护已读状态；见实现方案第五条要点。

### message 消息

| 字段 | 类型 | 允许空 | 说明 |
| --- | --- | --- | --- |
| `conversation_id` | BIGINT UNSIGNED | 否 | `conversation.id` |
| `sender_id` | BIGINT UNSIGNED | 否 | 发送人 |
| `content` | TEXT | 是 | 消息正文（`msg_type = file` 时存文件标识说明） |
| `msg_type` | VARCHAR(20) | 否 | `text` / `file` / `system`，默认 `text` |
| `ref_type` | VARCHAR(30) | 是 | 消息级引用（如引用某条成果） |
| `ref_id` | BIGINT UNSIGNED | 是 | 消息级引用主键 |

索引：`idx_message_conversation (conversation_id, id)`。

## 五、统计类

### activity_log 行为埋点流水

**贡献度分析的唯一数据来源。** 任何写入业务数据的动作都应在同一事务内追加一条记录。

| 字段 | 类型 | 允许空 | 说明 |
| --- | --- | --- | --- |
| `user_id` | BIGINT UNSIGNED | 否 | 行为人 |
| `team_id` | BIGINT UNSIGNED | 否 | 归属课题组（统计口径以团队为单位） |
| `type` | VARCHAR(40) | 否 | 行为类型，见下表 |
| `ref_type` | VARCHAR(30) | 是 | 关联对象类型 |
| `ref_id` | BIGINT UNSIGNED | 是 | 关联对象主键，用于**去重**（同一对象重复行为可识别） |
| `weight` | DECIMAL(5,2) | 否 | 该行为的基础权重，默认 `1.00`，最终口径见 03 号文档 |
| `created_at` | DATETIME | 否 | 发生时间，默认当前时间 |

索引：`idx_log_team_user_time (team_id, user_id, created_at)`；`idx_log_team_type (team_id, type)`；`idx_log_user_time (user_id, created_at)`。

`type` 建议取值：

| 取值 | 触发场景 |
| --- | --- |
| `task_create` | 新建任务 |
| `task_done` | 完成任务 |
| `comment_create` | 在业务对象下发表评论 |
| `literature_upload` | 上传文献 |
| `literature_read` | 标记文献已读 |
| `meeting_create` | 创建会议记录 |
| `meeting_attend` | 参加会议 |
| `achievement_submit` | 登记成果 |
| `milestone_done` | 完成里程碑 |

> **`ref_id` 是反刷分的关键**：统计时可对同一 `(type, ref_id)` 的行为去重或做衰减，避免用重复点击刷高分数。
